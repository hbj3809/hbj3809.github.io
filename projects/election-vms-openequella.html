프로젝트 개요
무엇을, 왜 만들었나

해외 선거관리 시스템(VMS)에서 유권자 수백만 명 규모의 데이터를 일괄 처리하고, 접근 로그 감사·데이터 암호화와 선거별 맞춤 리포트를 구현했습니다(기여도 60%). 같은 해 오픈소스 디지털 저장소 OpenEQUELLA 를 Java·Scala 로 확장해 콘텐츠 스키마·계층 구조와 Wowza 연계 스트리밍 API 를 개발하고, 지방자치단체·국내 대기업에 납품했습니다(기여도 70%).

프로젝트 개요

한 해 동안 성격이 다른 두 과제를 맡았습니다. 하나는 해외 선거에 쓰인 선거관리 시스템(VMS)으로, 여러 선거 장소에서 모인 유권자·투표 데이터를 중앙에서 일괄 처리하고 집계·보고하는 시스템입니다. 다른 하나는 오픈소스 디지털 저장소 OpenEQUELLA 를 고객 요구에 맞게 확장한 콘텐츠 저장소로, 지방자치단체와 국내 대기업에 납품했습니다.

선거 데이터는 무결성과 접근 통제가, 콘텐츠 저장소는 분류 체계와 영상 전달이 중심이었습니다.

  • 기간: 2021.01 ~ 2021.12 (휴먼텍소프트 솔루션사업부 · 대리)
  • 과제 ①: 해외 선거관리 시스템 — 유권자 수백만 명 규모, 여러 선거 장소에서 장소당 수십만 건의 데이터·트랜잭션
  • 과제 ②: OpenEQUELLA 기반 디지털 콘텐츠 저장소 — 지방자치단체(공공 부문)·국내 대기업 납품
  • 내 역할: 백엔드 개발 참여 — 선거관리 시스템 기여도 60%, 콘텐츠 저장소 기여도 70%
  • 맡은 부분: 유권자 데이터 일괄 처리, 선거별 맞춤 리포트, 접근 로그 감사·데이터 암호화, 저장소 콘텐츠 스키마·계층 구조 정의, Wowza 연계 스트리밍 API
  • 같은 시기 2021.09 까지 온라인 부정시험방지 솔루션(별도 프로젝트) PM 을 병행

CASE 01 · 대용량처리

장소당 수십만 건 일괄 적재와 투표 데이터 무결성 초안

1문제 상황

여러 선거 장소에서 장소당 수십만 건의 유권자·투표 데이터와 트랜잭션이 중앙으로 모였습니다. 유권자 수백만 명 규모의 데이터를 적재하고 집계해야 했고, 집계 결과가 선거 결과와 직결되어 한 건의 오류나 무단 변경도 신뢰를 흔들 수 있었습니다.

2원인 분석

대량 데이터를 한꺼번에 넣으면 형식 오류·중복·누락 건이 섞여 들어가도 바로 드러나지 않고, 적재 이후에는 누가 언제 무엇을 바꿨는지 추적하기 어렵습니다. 유권자 개인정보가 평문으로 남는 것도 위험 요소였습니다.

3해결 과정
  1. 장소 단위 묶음으로 읽어 처리하는 일괄 적재(배치) 구성
  2. 검증 단계를 저장과 분리해 오류 건을 따로 모으고 원천 수정 후 재적재
  3. 유권자 개인정보 필드를 저장 시점에 암호화
  4. 적재 작업과 관리자 조회를 접근 감사 로그로 기록
  5. 저장된 데이터에서 장소별·선거별 집계를 만들어 보고서로 연결
4결과

유권자 수백만 명 규모, 장소당 수십만 건의 데이터를 처리하고, 접근 로그 감사·데이터 암호화로 투표 데이터를 지켰고, 집계 대사에서 불일치 0건(무결성 100%)이었습니다(기여도 60%).

CASE 02 · 리포트설계

선거마다 다른 보고서 요구 초안

1문제 상황

선거마다 집계 단위와 보고서 양식에 대한 요구가 달랐습니다. 관리자는 정식 보고서와 함께 진행 현황을 화면에서 바로 보고 싶어 했습니다.

2원인 분석

보고서마다 조회·출력 코드를 따로 만들면 선거 수만큼 코드가 늘고, 양식 하나를 바꿀 때마다 개발과 배포가 필요해집니다.

3해결 과정
  1. 장소별·선거별 집계를 공통 단계로 두고 보고서는 그 결과만 읽도록 분리
  2. Crystal Reports 템플릿으로 선거별 맞춤 보고서 양식 작성
  3. Chart.js 로 화면 현황 차트 구성
4결과

같은 집계 결과에서 선거별 맞춤 보고서와 현황 차트를 함께 제공했습니다.

집계는 하나, 보고서 양식은 템플릿으로 여러 개

배운 점

자주 바뀌는 것(양식)과 잘 바뀌지 않는 것(집계)을 나누면 요구 변경이 코드 변경으로 번지지 않습니다.

이 부분은 근거 자료가 적어 기술 스택과 당시 환경을 바탕으로 쓴 초안입니다. 게시 전에 사실과 다른 곳이 없는지 확인해 주세요.

CASE 03 · 콘텐츠플랫폼

오픈소스 저장소를 고객 요구에 맞추기 초안

1문제 상황

지방자치단체와 국내 대기업 고객에게 디지털 콘텐츠 저장소를 납품해야 했습니다. 고객은 자기 업무에 맞는 콘텐츠 분류 체계와 영상 콘텐츠 재생을 원했습니다.

2원인 분석

OpenEQUELLA 는 항목·첨부·검색 같은 기본 기능을 갖췄지만, 고객별 메타데이터 형식과 분류 계층은 직접 정의해야 했고 영상 스트리밍은 별도 서버와 이어 줄 연결 고리가 필요했습니다.

3해결 과정
  1. 저장소와 같은 Java·Scala 로 OpenEQUELLA 커스터마이징
  2. 고객 업무에 맞춘 콘텐츠 스키마(메타데이터 형식) 정의
  3. 콘텐츠를 탐색할 계층 구조 분류 정의
  4. 영상 첨부를 Wowza 스트리밍 서버로 잇는 스트리밍 연계 API 개발
4결과

지방자치단체·국내 대기업에 콘텐츠 저장소를 납품했습니다(기여도 70%).
