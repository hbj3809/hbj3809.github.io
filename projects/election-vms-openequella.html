프로젝트 개요
무엇을, 왜 만들었나

해외 선거관리 시스템(VMS)에서 유권자 수백만 명 규모의 데이터를 일괄 처리하고, 접근 로그 감사·데이터 암호화와 선거별 맞춤 리포트를 구현했습니다(기여도 60%). 같은 해 오픈소스 디지털 저장소 OpenEQUELLA 의 원본 코드를 Java·Scala 로 고객 요구에 맞게 고쳐 콘텐츠 스키마·계층 구조와 Wowza 연계 스트리밍 API 를 구현하고, 지방자치단체·국내 대기업에 납품했습니다(기여도 70%).

문제해결 사례 3개 보기

개요한 해, 두 과제

한 해 동안 성격이 다른 두 과제를 맡았습니다. 하나는 해외 선거에 쓰인 선거관리 시스템(VMS)으로, 여러 선거 장소에서 모인 유권자·투표 데이터를 중앙에서 일괄 처리하고 집계·보고하는 시스템입니다. 다른 하나는 오픈소스 디지털 저장소 OpenEQUELLA 를 고객 요구에 맞게 고친(커스터마이징한) 콘텐츠 저장소로, 지방자치단체와 국내 대기업에 납품했습니다.

선거 데이터는 무결성과 접근 통제가, 콘텐츠 저장소는 분류 체계와 영상 전달이 중심이었습니다.

  • 과제 ①: 해외 선거관리 시스템 — 유권자 수백만 명 규모, 여러 선거 장소에서 장소당 수십만 건의 데이터·트랜잭션
  • 과제 ②: OpenEQUELLA 기반 디지털 콘텐츠 저장소 — 지방자치단체(공공 부문)·국내 대기업 납품
  • 맡은 부분: 유권자 데이터 일괄 처리, 선거별 맞춤 리포트, 접근 로그 감사·데이터 암호화, OpenEQUELLA 커스터마이징(콘텐츠 스키마·계층 구조), Wowza 연계 스트리밍 API
  • 같은 시기 2021.09 까지 온라인 부정시험방지 솔루션(별도 프로젝트) PM 을 병행

선거관리 시스템 아키텍처

선거 장소별로 모인 데이터를 중앙 시스템이 묶음 단위로 받아 검증한 뒤 저장하고, 저장된 데이터에서 장소별·선거별 집계와 집계 대사를 거쳐 선거별 보고서와 관리자 화면의 현황 차트를 만드는 구조입니다. 데이터는 암호화하고, 적재 작업과 관리자 조회는 감사 로그로 남깁니다. 이 구조에서 백엔드 구현을 맡았습니다.

유권자 데이터 처리 흐름

장소당 수십만 건이 한 번에 들어오는 구조라, 묶음 단위로 읽고 검증한 뒤 저장하는 흐름입니다. 검증에서 오류가 나오면 원천을 고친 뒤 해당 장소 묶음 전체를 다시 넣습니다. 저장한 데이터는 집계와 집계 대사를 거쳐 보고서·차트로 이어집니다. 이 흐름을 구현했습니다.

선거관리 시스템 개념 데이터 모델

선거 → 선거 장소 → 유권자의 계층을 축으로, 적재 묶음과 검증 오류, 장소별 집계, 보고서, 접근 감사 로그를 둘러 배치한 개념 모델입니다. 실제 테이블 이름이 아니라 개념 이름입니다.

디지털 콘텐츠 저장소 구조

OpenEQUELLA 의 항목·첨부·검색 기능을 바탕으로, 원본 코드를 고객 요구에 맞게 고쳐 고객별 콘텐츠 스키마와 계층 구조 분류를 구현했습니다. 영상은 Wowza 스트리밍 서버에서 받아 저장소의 스트리밍 연계 API 를 거쳐 사용자에게 전달합니다. 저장소를 처음부터 만들지 않고 오픈소스 원본 코드를 고객 요구에 맞게 고치는 방식입니다.

콘텐츠 저장소 개념 데이터 모델

스키마가 컬렉션의 메타데이터 형식을 정하고, 항목은 계층 구조의 여러 분류에 걸릴 수 있으며, 영상 첨부는 스트리밍 자산으로 이어지는 개념 모델입니다.

영상 콘텐츠 재생 흐름

사용자는 계층 구조로 콘텐츠를 찾고, 영상을 재생하면 스트리밍 연계 API 가 항목·첨부 정보로 Wowza 에 스트림을 요청합니다. Wowza 가 보낸 영상은 연계 API 를 거쳐 사용자에게 전달됩니다.

설계 원칙구현하며 따른 것

적재는 실시간이 아닌 묶음(배치)으로

데이터가 선거 장소 단위로 모여 들어와, 장소 묶음 단위로 읽고 검증하고 다시 넣을 수 있는 일괄 처리(배치)로 구현했습니다.

검증을 저장 앞에 두고 묶음 단위로 재적재

저장 전에 검증하고, 오류가 나온 장소 묶음은 원천을 고친 뒤 묶음 전체를 다시 넣도록 구현했습니다.

데이터는 암호화, 적재·조회는 감사 로그로

적재 작업과 관리자 조회가 기록으로 남아 있어야 집계 결과를 믿을 수 있습니다. 접근 로그 감사와 데이터 암호화를 무결성의 두 축으로 구현했고, 무결성 기준은 집계 대사에서 불일치 0건이었습니다.

보고서 양식은 코드 밖 템플릿으로

선거마다 다른 보고서는 Crystal Reports 템플릿으로, 진행 현황은 관리자 화면의 Chart.js 차트로 나눠 구현했습니다.

저장소는 새로 만들지 않고 오픈소스를 고쳐 씀

메타데이터 스키마·분류 계층·검색을 갖춘 OpenEQUELLA 를 바탕으로, 저장소와 같은 언어(Java·Scala)로 원본 코드를 고객 요구에 맞게 고쳤습니다.

영상은 전용 스트리밍 서버에서, 연계 API 를 거쳐 전달

영상 스트리밍은 Wowza 서버가 맡고, 저장소의 연계 API 가 Wowza 의 영상을 받아 사용자에게 전달하도록 구현했습니다.

성과

선거관리 시스템은 실제 선거에 적용되어 유권자 수백만 명 규모, 장소당 수십만 건의 데이터·트랜잭션을 처리했습니다. 접근 로그 감사·데이터 암호화로 투표 데이터를 지켰고, 집계 대사에서 불일치 0건(무결성 100%)이었습니다. 콘텐츠 저장소는 지방자치단체와 국내 대기업에 납품했습니다.

  • 선거관리 시스템: 유권자 수백만 명 규모 일괄 처리, 접근 로그 감사·데이터 암호화, 집계 대사 불일치 0건(무결성 100%)

  • 콘텐츠 저장소: OpenEQUELLA 커스터마이징(콘텐츠 스키마·계층 구조), Wowza 연계 스트리밍 API 구현, 지방자치단체·국내 대기업 납품

CASE 01 · 대용량처리

장소당 수십만 건 일괄 적재와 투표 데이터 무결성

1문제 상황

여러 선거 장소에서 장소당 수십만 건의 유권자·투표 데이터와 트랜잭션이 중앙으로 모였습니다. 유권자 수백만 명 규모의 데이터를 적재하고 집계해야 했고, 집계 결과가 선거 결과와 직결되어 한 건의 오류나 무단 변경도 신뢰를 흔들 수 있었습니다.

2원인 분석

대량 일괄 적재에서 오류와 무단 변경을 막아야 했습니다. 적재하는 경로에서 데이터를 검증해야 했고, 적재한 뒤에도 누가 언제 무엇을 했는지 추적할 수 있어야 했습니다. 무결성은 집계 대사에서 불일치가 한 건도 없어야 한다는 기준으로 봤습니다.

3해결 과정
  1. 장소 단위 묶음으로 읽어 처리하는 일괄 적재(배치) 구현
  2. 검증에 걸린 장소 묶음은 원천 수정 후 묶음 단위로 재적재 구현
  3. 데이터 암호화 구현
  4. 적재 작업과 관리자 조회를 남기는 접근 감사 로그 구현
  5. 저장된 데이터에서 장소별·선거별 집계를 만들어 보고서로 연결
4결과

실제 선거에 적용되어 유권자 수백만 명 규모, 장소당 수십만 건의 데이터를 처리했고, 접근 로그 감사·데이터 암호화로 투표 데이터를 지켰으며, 집계 대사에서 불일치 0건(무결성 100%)이었습니다(기여도 60%).

CASE 02 · 리포트구현

선거마다 다른 보고서 요구

1문제 상황

선거마다 집계 단위와 보고서 양식에 대한 요구가 달랐습니다. 정식 보고서와 함께 관리자 화면에서 진행 현황도 보여 줘야 했습니다.

2원인 분석

보고서마다 조회·출력 코드를 따로 만들면 선거 수만큼 코드가 늘고, 양식 하나를 바꿀 때마다 개발과 배포가 필요해집니다.

3해결 과정
  1. 공통 집계 결과를 읽는 선거별 보고서 구현
  2. Crystal Reports 템플릿으로 선거별 맞춤 보고서 양식 작성
  3. Chart.js 로 관리자 화면의 진행 현황 차트 구현
4결과

같은 집계 결과에서 선거별 맞춤 보고서와 현황 차트를 함께 제공했습니다.

집계는 하나, 보고서 양식은 템플릿으로 여러 개

배운 점

자주 바뀌는 보고서 양식(템플릿)과 잘 바뀌지 않는 집계를 나눠 두면 요구 변경이 코드 변경으로 번지지 않는다는 점을, 이 구조를 구현하며 배웠습니다.

CASE 03 · 콘텐츠플랫폼

오픈소스 저장소를 고객 요구에 맞추기

1문제 상황

지방자치단체와 국내 대기업 고객에게 디지털 콘텐츠 저장소를 납품해야 했습니다. 고객은 자기 업무에 맞는 콘텐츠 분류 체계와 영상 콘텐츠 재생을 원했습니다.

2원인 분석

OpenEQUELLA 는 항목·첨부·검색 같은 기본 기능을 갖췄지만, 고객별 메타데이터 형식과 분류 계층은 고객 업무에 맞게 만들어야 했고, 영상 스트리밍은 별도 서버(Wowza)와 이어 줄 연결 고리가 필요했습니다.

3해결 과정
  1. 저장소와 같은 Java·Scala 로 OpenEQUELLA 커스터마이징
  2. 고객 업무에 맞춘 콘텐츠 스키마(메타데이터 형식) 구현
  3. 콘텐츠를 탐색할 계층 구조 분류 구현
  4. Wowza 스트리밍 서버의 영상을 받아 사용자에게 전달하는 스트리밍 연계 API 구현
4결과

지방자치단체·국내 대기업에 콘텐츠 저장소를 납품했습니다(기여도 70%).

기본 기능을 고객 요구에 맞게 고친 구조

배운 점

원본을 직접 고치면 버전을 올릴 때 수정분을 다시 맞춰야 해서, 고친 곳을 따로 관리해야 한다는 점을 배웠습니다.

정리:이 프로젝트에서 남긴 것

선거관리 시스템에서는 적재 경로의 검증·암호화·감사 로그와 템플릿 보고서를 구현했고, 이 시스템은 실제 선거에 적용되어 집계 대사 불일치 0건이었습니다. 콘텐츠 저장소는 OpenEQUELLA 원본을 고쳐 고객별 스키마·계층 분류와 Wowza 연계 스트리밍 API 를 더해 납품했습니다.
