개요비대면 시험 감독을 돕는 실시간 영상과 자동 탐지

코로나19 팬데믹으로 비대면 시험 수요가 급증하던 시기에 휴먼텍소프트 솔루션사업부에서 온라인 부정시험방지 솔루션 HT-OPP를 맡았습니다.

핵심은 두 가지입니다. 하나는 응시자의 웹캠 영상을 감독관에게 실시간으로 보여 주는 것이고, 다른 하나는 부정행위로 볼 수 있는 상태를 모델이 자동으로 잡아 감독관과 응시자에게 알리는 것입니다.

탐지 모델은 가져다 쓰지 않고 직접 학습했습니다. 시험장 환경과 응시자 환경을 직접 구성하고, 다양한 각도⁠·자세⁠·동작 데이터를 추가해 학습했습니다. 판정은 응시자 영상 프레임을 서버로 보내 서버에서 합니다.

기획⁠·개발⁠·QA⁠·납품의 전 주기를 혼자 수행했고(기여도 100%), 솔루션을 상용화해 교육기관에 납품했습니다. 교육기관 납품 시험에서는 한 시험에 응시자 100명 내외를 동시에 감독했습니다.

  • 대상교육기관의 비대면 시험
  • 규모한 시험에 응시자 100명 내외 동시 감독(교육기관 납품 시험 기준, 측정값이 아닌 운영 규모)
  • 탐지 모델시험장⁠·응시자 환경을 직접 구성하고 다양한 각도⁠·자세⁠·동작 데이터를 추가해 직접 학습, 서버에서 판정
  • 결과상용화 완료, 교육기관 납품

아키텍처영상 경로와 탐지⁠·알림 경로

응시자 웹캠 영상은 두 경로로 갑니다. 감독용 영상은 WebRTC P2P 다중 연결로 감독관 화면에 실시간 전달됩니다. 판정용 영상 프레임은 서버로 보내지고, 서버의 탐지 모델(직접 학습, OpenCV⁠·TensorFlow)이 시야 이탈⁠·자리 이탈을 판정합니다. 이탈이 5초 이상 이어지면 Socket.IO로 감독관과 응시자에게 알립니다.

  • 감독용 영상(P2P)과 판정용 영상 프레임(서버)의 경로를 나눠 구성
  • 탐지⁠·판정은 서버에서 실행하고, 알림은 감독관과 응시자 양쪽으로 보냄
  • 서버 애플리케이션은 Java⁠·Spring, 서비스 데이터와 탐지⁠·알림 이력은 MariaDB⁠·PostgreSQL에 저장

핵심 흐름시험 세션 한 번

감독관이 시험실을 열고 응시자가 들어오면 감독관과 응시자 사이에 WebRTC P2P 영상 연결이 맺어집니다. 시험이 끝날 때까지 응시자 영상 프레임이 서버로 가서 탐지와 판정이 반복됩니다. 이탈이 5초 이상 이어지면 알림을 한 번 보내고, 응시자가 돌아올 때까지 다시 알리지 않습니다.

판정 규칙응시자 감시 상태 전이

판정 기준은 순간 동작이 아니라 지속 시간입니다. 시야 이탈이나 자리 이탈이 감지돼도 바로 알리지 않습니다. 그 상태가 5초 이상 이어질 때만 감독관과 응시자에게 알립니다. 알림은 한 번만 보내고, 응시자가 정면을 보거나 자리로 돌아오면 다시 정상 응시 상태로 돌아가 판정을 이어 갑니다.

개념 데이터 모델

실제 테이블 구조가 아니라 시험 감독 업무를 이루는 개념을 정리한 모델입니다. 시험실 단위로 감독관과 응시자가 묶이고, 응시마다 탐지 이벤트와 알림이 쌓입니다.

설계 결정왜 이렇게 만들었나

기술 선택과 판정 규칙을 어떻게 정했는지 정리했습니다.

감독 영상은 P2P, 판정은 서버에서

감독관이 보는 영상은 서버가 중계하지 않고 WebRTC P2P로 감독관 브라우저에 바로 보냅니다. 부정행위 판정은 응시자 영상 프레임을 서버로 보내 서버의 탐지 모델이 맡습니다. 보는 경로와 판정하는 경로를 나눈 구조입니다.

탐지 모델은 가져오지 않고 직접 학습

시험장 환경과 응시자 환경을 직접 구성하고, 다양한 각도⁠·자세⁠·동작 데이터를 추가해 모델을 학습했습니다. 응시자마다 조명과 카메라 각도가 달라, 실제 응시 화면에 가까운 데이터가 필요했습니다.

탐지 대상은 행동이 분명한 두 가지

시야 이탈(정면을 보지 않음)과 자리 이탈(일어나거나 화각을 벗어남)에 집중했습니다. 행동 자체는 분명해 딥러닝으로 판정하기 어렵지 않은 조건이었습니다. 다만 조명⁠·카메라 각도에 따른 오탐이 있어 학습 데이터를 보강해 대응했습니다.

순간 동작이 아니라 지속 시간으로 판정

고개를 잠깐 돌리는 순간까지 알리면 감독관도 응시자도 알림에 지칩니다. 그래서 이탈 상태가 5초 이상 이어질 때만 알림을 보냈습니다.

판단은 감독관이, 교정은 응시자가

알림을 감독관 화면과 응시자 화면에 함께 보냅니다. 응시자는 바로 자세를 고칠 수 있고, 부정행위 처리 여부는 감독관이 판단합니다.

주요 기능과 구현

기능은 실시간 영상 감독과 자동 탐지⁠·알림, 두 가지로 나뉩니다.

  • 실시간 영상 감독WebRTC 오픈소스를 커스터마이징한 P2P 다중 연결(Multi-connection) 기반 실시간 영상 감독 시스템
  • 부정행위 자동 탐지응시자 영상 프레임을 서버로 보내 판정하는 OpenCV⁠·TensorFlow 기반 시야 이탈(정면 응시가 아닐 때)⁠·자리 이탈(자리에서 일어나거나 화각을 벗어날 때) 2개 조건 탐지 모델
  • 탐지 모델 직접 학습시험장 환경과 응시자 환경을 직접 구성하고, 다양한 각도⁠·자세⁠·동작 데이터를 추가해 학습(공개 모델을 가져다 쓴 것이 아님)
  • 지속 시간 판정두 조건 중 하나라도 5초 이상 이어질 때만 부정행위 의심으로 판정
  • 실시간 알림Socket.IO로 감독관⁠·응시자에게 알림 UI⁠·자동 메시지 전송
  • 전 주기 단독 수행기획 → 개발 → QA → 납품

성과와 숫자의 성격

탐지 정확도 100%는 납품한 교육기관의 피드백 기준입니다. 몇 명이 적발돼 부정행위로 처리됐는지 같은 운영 지표는 받지 못했습니다. 응시자 100명 내외는 교육기관 납품 시험의 운영 규모이며, 따로 측정한 값이 아닙니다.

문제 현황

문제 상황

응시자마다 조명과 웹캠 각도가 달랐습니다. 이 때문에 정상적으로 응시하는 모습을 시야 이탈이나 자리 이탈로 잘못 탐지하는 경우(오탐)가 실제로 생겼습니다. 오탐이 그대로 알림이 되면 감독관은 알림을 믿기 어렵고, 응시자는 시험에 집중하기 어렵습니다.

원인 분석

조명이나 카메라 각도가 바뀌면 같은 자세도 모델에게는 다르게 보입니다. 학습 데이터가 실제 응시 환경의 다양한 각도⁠·자세를 충분히 담지 못하면 정상 응시를 이탈로 잘못 판정할 수 있습니다.

해결 과정
  1. 시험장 환경과 응시자 환경을 직접 구성해 실제 응시 화면에 가까운 조건을 마련
  2. 다양한 각도⁠·자세⁠·동작 데이터를 추가해 탐지 모델을 직접 학습(공개 모델을 가져다 쓰지 않음)
  3. 순간 판정 결과를 바로 알리지 않고, 이탈 상태가 5초 이상 이어질 때만 알림으로 이어지게 해 짧은 오판정이 곧바로 알림이 되지 않게 함

배운 점

탐지할 행동이 분명해도 조명과 카메라 각도 같은 응시 환경이 다양하면 오탐이 생깁니다. 실제 응시 환경에 가까운 데이터를 직접 갖추는 일이 모델만큼 중요했습니다.

CASE 02 / 02실시간 영상

응시자 네트워크 끊김⁠·지연감독 화면과 서버 판정이 함께 흔들리는 문제

문제 현황

끊김⁠·지연
  • 응시자마다 다른 장소⁠·다른 네트워크로 시험에 접속
  • 실제 운영에서 네트워크 품질 차이로 끊김⁠·지연 발생
  • 감독관 화면 영상이 멈추거나 늦어짐
  • 서버가 판정에 쓸 프레임도 늦거나 비게 됨

원인 분석

통제 불가
  • 네트워크 품질은 응시자 쪽 환경이라 서버가 통제할 수 없음
  • 감독 영상은 응시자→감독관 P2P, 판정 프레임은 응시자→서버
  • 응시자 네트워크가 흔들리면 두 경로가 함께 영향을 받음

해결 과정

끊김 대응
  1. 연결이 끊기면 자동으로 다시 연결
  2. 네트워크가 나쁘면 전송 주기⁠·해상도를 낮춰 보내는 양을 줄임
  3. 프레임이 안 들어오는 동안 부정행위 판정 멈춤(오탐 방지)

결과

판정 유지
  • 끊기거나 느려질 때도 판정이 이어지게 함
  • 개선 정도를 따로 잰 수치는 없음
  • 상용화해 한 시험 응시자 100명 내외 규모로 교육기관에 납품
전체 설명 보기
문제 상황

응시자는 각자 다른 장소에서 자기 네트워크로 시험에 접속합니다. 실제 운영에서 응시자마다 네트워크 품질이 달라 끊김과 지연이 생겼습니다. 영상 프레임이 늦게 오거나 빠지면 감독관 화면의 영상이 멈추거나 늦어지고, 서버가 판정에 쓸 프레임도 늦거나 비게 됩니다.

원인 분석

네트워크 품질은 응시자 쪽 환경이라 서버가 통제할 수 없습니다. 감독용 영상은 응시자에서 감독관으로 P2P로 가고 판정용 프레임은 응시자에서 서버로 가기 때문에, 응시자 네트워크가 흔들리면 감독 화면과 서버 판정이 함께 영향을 받습니다.

해결 과정
  1. 연결이 끊기면 자동으로 다시 연결
  2. 네트워크 상태가 나쁘면 프레임 전송 주기⁠·해상도를 낮춰 보내는 양을 줄임
  3. 프레임이 들어오지 않는 동안에는 부정행위 판정을 멈춰, 네트워크 문제를 부정행위로 잘못 판정하지 않게 함(오탐 방지)
결과

이 조치로 응시자 네트워크가 끊기거나 느려질 때도 판정이 이어지게 했습니다(개선 정도를 따로 잰 수치는 없음). 솔루션은 상용화해 한 시험에 응시자 100명 내외 규모로 교육기관에 납품했습니다.

배운 점

실시간 영상 서비스는 응시자 쪽 네트워크를 통제할 수 없다는 전제에서 출발해야 합니다. 감독 화면과 판정처럼 영상이 쓰이는 곳이 여럿이면, 네트워크 문제도 그 경로마다 따로 봐야 합니다.

정리이 프로젝트에서 남긴 것

응시자마다 조명⁠·카메라 각도⁠·네트워크 상태가 달라 오탐과 끊김⁠·지연이 생겼습니다. 각도⁠·자세⁠·동작 데이터를 더해 모델을 직접 학습하고, 5초 지속 판정과 프레임이 없을 때의 판정 멈춤으로 오판정이 곧바로 부정행위 알림이 되지 않게 했습니다.
