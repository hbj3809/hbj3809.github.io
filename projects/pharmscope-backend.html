프로젝트 · 백엔드

멀티테넌트 데이터 분석 SaaS 백엔드

여러 제약사가 한 서비스와 DB 를 함께 쓰는 의약품 유통 데이터 분석 서비스 pharmscope 의 백엔드를 처음부터 설계·구현했습니다.

문제

인증만 있던 상태에서 공개 전까지 계약사 관리·운영관리(공지·FAQ·문의)·보안 로그·계정 관리·실시간 알림을 갖춰야 했습니다. 고객사들이 한 인스턴스를 공유하므로 다른 회사의 데이터가 보이는 순간 서비스가 끝납니다(OWASP API 1위, 객체 수준 권한 우회).

설계

  • 인증: access 토큰은 메모리, refresh 는 HTTP-only 쿠키로 나눈 자체 JWT. 7단계 로그인 체인(역할·계약 상태·IP 허용 목록·실패 잠금), refresh 회전·재사용 탐지·블랙리스트·계정당 1세션.
  • 테넌트 격리: 회사 식별자는 요청 값이 아니라 토큰 클레임에서만 받는다. 리소스 API 마다 "다른 회사로 접근하면 403" 통합 시험을 넣도록 규칙화했다.
  • 모듈러 모놀리스: 배포 단위는 하나로 두고 도메인 모듈(어드민·고객·운영·실시간 알림)을 추가하는 구조. 이후 매출 분석 모듈도 같은 방식으로 붙었다.
  • 실시간 알림: 여러 파드에 흩어진 SSE 연결로 전하기 위해 DB inbox 에 먼저 저장하고 Kafka 로 발행, 파드마다 다른 consumer group 이 자기 연결에 push.

결함을 먼저 찾기

공개 직전, AI 에이전트로 10개 축(테넌트 격리·인젝션·파일 업로드·토큰·세션 등)을 병렬로 찾고 발견마다 다른 에이전트가 반박하는 감사를 돌려, 살아남은 고위험 2건·중위험 8건만 시험과 함께 고쳤습니다. 서명키가 주입되지 않으면 기본값으로 조용히 뜨던 문제는 기동 실패로 바꿨고, 일반 관리자가 상위 관리자 계정을 건드릴 수 있던 경로를 막았습니다.

QA 재검증에서는 "삭제한 계정의 이메일 재사용"을 넣는 과정에서, 재발송 경로가 계정 번호로 찾은 뒤 이메일로 다시 해석하는 바람에 다른 회사 신규 계정의 비밀번호를 리셋할 수 있는 교차 오조작을 공개 전에 찾았습니다. 신원의 기준을 계정 번호로 고정하고 같은 유형을 전수 점검했습니다.

장애 원인 규명

자리를 비웠다 돌아오면 모든 탭이 로그아웃되던 문제는, 만료 직후 여러 요청이 같은 1회용 refresh 토큰으로 동시에 회전하다 재사용 공격으로 오판된 레이스였습니다. 사용자별 분산 락과 직전 토큰의 짧은 유예 재응답으로 풀고, 동시 갱신 4건이 같은 토큰으로 모이는 회귀 시험으로 고정했습니다. 새로고침 복원 기능을 넣을 때는 AI 적대 리뷰가 "이 기능이 토큰 발급 통로가 된다"는 치명 결함을 찾아 병합 전에 막았습니다.
