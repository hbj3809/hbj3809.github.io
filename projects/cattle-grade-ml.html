프로젝트 개요
무엇을, 왜 만들었나

축우 관련 사업부는 매월 사육 중인 개체의 육질·육량 데이터를 보고 다음 달 등급을 수기로 예측해 보고했고, 정확도는 60~70%로 참고용에 그쳤습니다. 석사 과정에서 연구한 Random Forest·XGBoost·LightGBM Stacking Ensemble 모델을 이 보고 업무에 붙이자는 AI 서비스 도입 품의를 직접 작성해 확정까지 이끌었고, 등급 예측 서비스를 대시보드 형태로 제공했습니다. 현업 적용 직후 85% 내외로 떨어진 정확도는 2개월간 하이퍼파라미터 튜닝·재학습·데이터 추가 확보로 89~91%까지 올렸습니다. SHAP 변수 중요도 분석 결과는 사양 관리 지표로 현업에 넘겼고, D등급 발생이 예상되는 거래처를 미리 찾는 고객 등급 예측 서비스는 현업 마케터·본부와 함께 미수금·계약 관리 업무에 적용했습니다.

AI 도입 품의 작성, 모델 설계·개발 주도, 학습 파이프라인 운영 · AI·빅데이터 영역 2인(본인·DBA 1인) + 현업 마케터·해당 본부 인력 협업

개요

축우 관련 사업부는 매월 농장·목장에서 사육 중인 개체의 육질·육량 데이터를 보고 다음 달 육질·육량 등급을 예측해 보고했습니다. 수기 예측 정확도는 60~70%로, 보고서는 참고용에 머물렀습니다. 석사 과정에서 연구한 축우 등급 예측 모델을 이 보고 업무에 붙이자는 AI 서비스 도입 품의를 직접 작성해 확정까지 이끌었고, 축우 개체의 성장 데이터와 도축 당시 육질·육량 지표로 도축 시 판정 등급을 예측하는 서비스를 대시보드 형태로 제공했습니다. 같은 기간 D등급 발생이 예상되는 거래처를 미리 골라내는 고객 등급 예측 서비스도 현업과 함께 적용했습니다.

  • 기간: 2023.03 ~ 2023.12 (선진 기술연구소 디지털혁신센터 재직, 석사 과정 병행)
  • 목표: 경험에 기대던 월간 등급 예측 보고를 데이터 기반 예측으로 전환
  • 내 역할: 도입 품의 작성·확정, 모델 설계·개발 주도, 학습 파이프라인 운영, SHAP 분석 결과의 현업 지표화
  • 팀: AI·빅데이터 영역 2인(본인·DBA 1인). 비즈니스 모델 적용은 현업 마케터·해당 본부 인력과 협업
  • 범위: 축우 등급 예측 대시보드, 고객 D등급 예측 서비스
  • 발판: 같은 시기 구축하던 SFA/CRM 프로젝트를 발판으로 AI 기능(축우 대시보드·D등급 예측)을 실제 업무에 반영
  • 근거 연구: 석사 학위 논문 「앙상블 모델을 활용한 축우 등급 판정 결과 예측 및 상관 관계 분석」

전체 구성 초안

원천 데이터를 정기 수집해 분석용 저장소에 쌓고, 학습 데이터로 가공한 뒤 Stacking Ensemble 로 축우 등급을 예측합니다. 고객 등급 예측은 별도 모델로 두고, 예측 결과는 대시보드와 거래처 목록으로, SHAP 분석은 사양 관리 지표로 현업에 나갑니다.

이 부분은 근거 자료가 적어 기술 스택과 당시 환경을 바탕으로 쓴 초안입니다. 게시 전에 사실과 다른 곳이 없는지 확인해 주세요.

모델 학습 흐름

논문에서 세운 학습 절차를 현업 모델의 뼈대로 그대로 썼습니다. 세 알고리즘을 같은 데이터로 각각 학습해 알고리즘별 최고 모델을 고르고, 이를 Stacking Ensemble 로 묶어 최종 정확도를 쟀습니다. 이어서 변수 중요도와 SHAP 으로 변수 간 관계를 분석해 새 지표로 쓸 변수를 추천했습니다.

  • 데이터: 소도체 이력·도축 정보·등급 평가 정보를 정의하고 파이프라인으로 수집
  • 보정: 전처리와 EDA 로 데이터 보정
  • 비교: 기본 변수만 쓴 경우와 추가 지표를 결합한 경우의 정확도 비교
  • 결합: 알고리즘별 최고 모델을 Stacking Ensemble 로 결합
  • 설명: Feature·Permutation Importance 측정 후 SHAP 으로 변수 간 상관 분석, 활용성 높은 변수를 신규 지표로 추천

이 부분은 근거 자료가 적어 기술 스택과 당시 환경을 바탕으로 쓴 초안입니다. 게시 전에 사실과 다른 곳이 없는지 확인해 주세요.

개념 데이터 모델 초안

실제 테이블 구조가 아니라 예측에 쓰인 데이터를 일반 개념으로 다시 그린 그림입니다. 개체 단위로 성장 기록·도축·판정 결과를 잇고, 예측 결과마다 모델 버전과 변수 기여도(SHAP)를 남기는 구조입니다. 거래처 쪽은 SFA/CRM 의 거래처·여신 개념을 빌려 고객 등급 예측의 대상으로 두었습니다.

모델 운영 단계

논문 검증에서 현업 운영까지 모델이 거친 단계입니다. 사업부에 제공하자 정확도가 한 번 내려갔고, 2개월 재튜닝을 거쳐 월간 예측 운영에 들어갔습니다.

설계 결정왜 이렇게 골랐나 초안

단일 모델 대신 Stacking Ensemble

같은 데이터로 Random Forest·XGBoost·LightGBM 을 각각 학습해 알고리즘별 최고 모델을 고른 뒤 결합. 한 알고리즘의 약점에 기대지 않고, 개별 모델과 최종 모델의 정확도를 나란히 비교할 수 있게 한 선택.

트리 계열 알고리즘 3종

개체 이력·도축·등급 평가처럼 수치와 범주가 섞인 표 형태 데이터. 변수 중요도를 바로 뽑을 수 있어 뒤의 설명 단계(SHAP)와 잘 맞는 계열로 한정.

예측값에 SHAP 근거를 붙여 전달

현업이 숫자를 믿고 쓰려면 '왜 이 등급인지'가 필요. Feature·Permutation Importance 로 전체 중요도를 보고 SHAP 으로 변수 간 관계를 분석해, 활용성 높은 변수를 사양 관리 지표로 제공.

새 업무 대신 기존 월간 보고에 얹기

사업부가 이미 매월 하던 '다음 달 등급 예측 보고'는 그대로 두고 예측 방식만 교체. 수기 예측과 같은 잣대(정확도)로 바로 비교 가능.

성과는 정확도로 재고, 오차율은 환산으로 표기

현업 보고가 정확도로 비교되므로 정확도로 측정. 예측 오차율 30~40%→9~11% 는 정확도에서 환산한 값이며 따로 잰 값이 아님을 함께 표기.

주요 기능 초안

축우 등급 예측 대시보드

사육 중인 개체의 성장 데이터와 도축 당시 육질·육량 지표로 도축 시 판정 등급을 예측. 사업부의 월간 등급 예측 보고에 쓰는 화면.

사양 관리 지표

SHAP 변수 중요도 분석 결과를 사양 관리 지표로 정리해 현업에 제공. 어떤 변수가 등급에 크게 작용했는지 예측 결과와 함께 확인.

고객 D등급 예측

D등급 발생이 예상되는 거래처를 미리 골라 현업 마케터·본부와 함께 미수금·계약 관리 업무 모델로 적용. 정확도 수치는 따로 제시하지 않음.

재튜닝·재학습

예측과 실제 판정 결과를 비교해 정확도가 떨어지면 하이퍼파라미터 튜닝·재학습·데이터 추가 확보로 복구. 현업 적용 직후 2개월간 이 과정을 거쳐 89~91% 확보.

성과

축우 등급 예측 정확도는 현업 수기 60~70%→최종 89~91%. 예측 오차율로 바꾸면 30~40%→9~11%(정확도 환산 값). 논문 단계 93% 에서 현업 적용 직후 85% 내외로 내려간 뒤, 2개월 튜닝·재학습·데이터 추가 확보로 회복. 고객 D등급 예측은 정확도 수치 없음. 이 AI 프로젝트 성과는 이후 그룹 계열사 공통 ERP 표준 모델 채택 과정에서도 긍정 요인으로 함께 인정됨.

CASE 01 · 모델개발

참고용에 그치던 수기 등급 예측을 데이터 기반 보고로

1문제 상황

축우 관련 사업부는 매월 사육 중인 개체의 육질·육량 데이터를 보고 다음 달 육질·육량 등급을 예측해 보고했습니다. 수기 예측 정확도는 60~70% 로, 보고서는 참고용으로만 쓰였습니다.

2원인 분석

담당자 경험에 기댄 판단이라 신뢰도가 낮았고, 보고서는 의사결정 자료가 아닌 참고 자료에 머물렀습니다.

3해결 과정
  1. 기존 월간 등급 예측 보고를 대상으로 AI 서비스 도입 품의 작성·확정
  2. 100만 건 축우 개체 데이터로 Random Forest·XGBoost·LightGBM 학습, 알고리즘별 최고 모델을 Stacking Ensemble 로 결합
  3. 등급 예측 서비스를 대시보드 형태로 사업부에 제공
  4. AI·빅데이터 영역은 DBA 1인과 2인으로 수행, 비즈니스 적용은 현업 마케터·본부 인력과 협업
4결과

축우 등급 예측 정확도 60~70%→89~91%, 예측 오차율 30~40%→9~11%(정확도 환산).

숫자로 본 변화

축우 등급 예측 정확도
60~70%(수기)→89~91%(모델 최종)
예측 오차율
30~40%→9~11%
정확도에서 환산한 값

월간 등급 예측 보고의 전/후 구조

배운 점

모델을 새 업무로 들이지 않고 이미 매월 하던 보고에 얹었기 때문에, 수기 예측과 같은 잣대(정확도)로 바로 비교할 수 있었습니다.

CASE 02 · 성능개선

논문 93% 가 현업에서 85% 로 — 2개월 재튜닝으로 89~91% 회복 초안

1문제 상황

석사 논문에서 100만 건 축우 개체 데이터로 검증한 모델은 정확도 93% 였습니다. 같은 모델을 사업부에 대시보드로 제공하자 정확도가 85% 내외로 내려갔습니다. 월간 등급 보고에 쓰려면 다시 끌어올려야 했습니다.

2원인 분석

논문 검증용 데이터와 사업부가 매월 쌓는 운영 데이터 사이의 차이, 그리고 논문 데이터에 맞춰 둔 하이퍼파라미터가 운영 데이터에 맞지 않은 것을 주된 원인으로 보았습니다.

3해결 과정
  1. 예측 결과와 실제 도축 판정 등급을 맞대어 정확도 저하 확인
  2. 하이퍼파라미터 재탐색
  3. 운영 데이터를 포함한 재학습
  4. 부족한 데이터 추가 확보·보완
  5. 2개월간 튜닝과 데이터 보완을 반복하며 정확도 재측정
4결과

정확도 85% 내외→89~91%. 현업 수기 예측(60~70%) 대비로는 예측 오차율 30~40%→9~11%(정확도 환산).

숫자로 본 변화

축우 등급 예측 정확도
85% 내외(현업 적용 직후)→89~91%
2개월 튜닝·재학습·데이터 추가 확보
참고: 논문 검증 정확도
93%→89~91%(현업 운영 데이터 기준)
검증 데이터가 달라 직접 비교 대상은 아님

진행 순서

  1. 적용 직후
    정확도 85% 내외사업부 제공 뒤 예측과 실제 판정 비교에서 저하 확인
  2. 이후 2개월
    튜닝·재학습·데이터 추가 확보 반복
  3. 튜닝 후
    최종 정확도 89~91%월간 등급 예측 보고에 사용
배운 점

논문 정확도는 출발점일 뿐이었습니다. 운영 데이터로 다시 재고 고치는 기간을 처음부터 일정에 넣어야 한다는 기준이 생겼습니다.

이 부분은 근거 자료가 적어 기술 스택과 당시 환경을 바탕으로 쓴 초안입니다. 게시 전에 사실과 다른 곳이 없는지 확인해 주세요.

CASE 03 · ETL 파이프라인

출처가 다른 개체·도축·판정 데이터를 학습용 한 벌로 초안

1문제 상황

등급 예측 모델을 만들려면 소도체 이력, 도축 정보, 등급 평가 정보를 먼저 정의하고 한곳에 모아야 했습니다.

2원인 분석

세 갈래 데이터는 만들어지는 곳과 기준이 달라, 그대로는 같은 개체 단위로 묶어 학습에 쓰기 어려웠습니다.

3해결 과정
  1. 예측에 쓸 소도체 이력·도축 정보·등급 평가 정보 항목 정의
  2. Apache Airflow 파이프라인으로 정기 수집, Amazon Redshift 에 적재
  3. 전처리와 EDA 로 데이터 보정
  4. 기본 변수만 쓴 경우와 추가 지표를 결합한 경우를 나눠 정확도 비교
  5. 알고리즘별 최고 모델을 골라 Stacking Ensemble 로 최종 정확도 측정
4결과

100만 건 축우 개체 데이터로 학습한 Stacking Ensemble 모델이 논문 데이터 기준 정확도 93% 를 기록했고, 이 절차가 현업 모델의 뼈대가 되었습니다.

숫자로 본 변화

논문 단계 최종 정확도
93%
100만 건 축우 개체 데이터, Stacking Ensemble

논문 단계 수집·가공 흐름의 전/후

배운 점

모델 정확도보다 먼저, 무엇을 같은 개체로 묶을지 정의하는 일이 학습의 출발점이었습니다.

CASE 04 · 현업연계

예측 숫자를 현업이 쓰는 지표로 — SHAP 변수 기여도 제공 초안

1문제 상황

등급 예측값만으로는 사업부가 사양 관리에서 무엇을 바꿔야 할지 알 수 없었습니다.

2원인 분석

여러 모델을 묶은 앙상블은 개별 예측의 근거를 바로 보여주지 못합니다. 근거 없는 숫자는 현업이 판단에 쓰기 어렵습니다.

3해결 과정
  1. Feature Importance·Permutation Importance 로 전체 변수 중요도 측정
  2. SHAP 으로 변수 간 상관 관계와 예측별 기여도 분석
  3. 활용성이 높은 변수를 신규 지표 후보로 추천
  4. 분석 결과를 사양 관리 지표로 정리해 현업에 제공
4결과

SHAP 기반 변수 중요도 분석 결과가 사양 관리 지표로 현업에 제공됨(정량 수치 없음). 이 AI 프로젝트 성과는 이후 그룹 계열사 공통 ERP 표준 모델 채택 과정에서도 긍정 요인으로 함께 인정됨.

예측 결과 전달 방식의 전/후

배운 점

예측값만으로는 현업이 움직이지 않았습니다. 무엇을 바꾸면 되는지를 변수로 보여줄 때 비로소 지표가 됐습니다.
