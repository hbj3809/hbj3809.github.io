프로젝트 개요
무엇을, 왜 만들었나

축우 관련 사업부는 매월 사육 중인 개체의 육질·육량 데이터를 보고 다음 달 등급을 수기로 예측해 보고했고, 정확도는 60~70%로 참고용에 그쳤습니다. 석사 과정에서 연구한 Random Forest, XGBoost, LightGBM 을 묶은 Stacking Ensemble 모델을 이 보고 업무에 붙이자는 AI 서비스 도입 품의를 직접 작성해 확정까지 이끌었고, 등급 예측 서비스를 대시보드 형태로 제공했습니다. 현업 적용 직후 정확도가 85% 내외로 떨어진 원인은 하이퍼파라미터·모델 조정 문제였고, 2개월간 하이퍼파라미터 튜닝, 예측과 실제 판정을 비교해 모델을 계속 개선하는 강화학습, 데이터 추가 확보로 89~91%까지 올렸습니다↑. SHAP 변수 중요도 분석 결과는 사양 관리 지표로 현업에 넘겼고, 여신·미수금과 실제 거래처 매출·주문 데이터로 D등급 발생이 예상되는 거래처를 미리 찾는 고객 등급 예측 서비스는 현업과 계산식을 함께 정하고, 마케터·본부와 미수금·계약 관리 업무에 적용했습니다.

개요목표·역할·범위

모델은 축우 개체의 성장 데이터와 도축 당시 육질·육량 지표로 도축 시 판정 등급을 예측합니다. 예측 결과는 사업부가 매월 올리던 다음 달 등급 예측 보고에 쓰였습니다.

  • 학업: 재직 중 석사 과정 병행
  • 목표: 경험에 기대던 월간 등급 예측 보고를 데이터 기반 예측으로 전환
  • 내 역할: 도입 품의 작성·확정, 모델 설계·개발 주도, 학습 파이프라인 운영, SHAP 분석 결과의 현업 지표화
  • 협업: 비즈니스 모델 적용은 현업 마케터·해당 본부 인력과 함께 진행
  • 범위: 축우 등급 예측 대시보드, 고객 D등급 예측 서비스
  • 발판: 같은 시기 구축하던 SFA/CRM 프로젝트를 발판으로 AI 기능(축우 대시보드·D등급 예측)을 실제 업무에 반영
  • 근거 연구: 석사 학위 논문 「앙상블 모델을 활용한 축우 등급 판정 결과 예측 및 상관 관계 분석」

석사 연구에서 출발한 모델이 품의·현업 적용·재튜닝을 거쳐 월간 보고에 자리 잡기까지의 순서입니다.

전체 구성

사내 목장·농장 데이터와 공공 축산물 이력 데이터를 정기 수집해 분석용 저장소에 쌓고, Spark 로 전처리·피처 생성을 분산 처리한 뒤 Stacking Ensemble 로 축우 등급을 예측합니다. 현업 적용 단계의 학습·튜닝·강화학습 루프는 Databricks 작업 공간(노트북·작업 스케줄)에서 관리했고, 예측과 실제 판정을 비교한 결과가 다시 이 루프로 들어갑니다. 고객 등급 예측은 거래처 여신·미수금과 실제 매출·주문 데이터를 쓰는 별도 모델로 두고, 예측 결과는 대시보드와 거래처 목록으로, SHAP 변수 중요도 분석은 사양 관리 지표로 현업에 나갑니다.

모델 학습 흐름

논문에서 세운 학습 절차를 현업 모델의 뼈대로 그대로 썼습니다. 세 알고리즘을 같은 데이터로 각각 학습해 알고리즘별 최고 모델을 고르고, 이를 Stacking Ensemble 로 묶어 최종 정확도를 쟀습니다. 이어서 변수 중요도와 SHAP 으로 변수 간 관계를 분석해 새 지표로 쓸 변수를 추천했습니다.

  • 데이터: 사내 목장·농장 데이터와 공공 축산물 이력 데이터에서 소도체 이력·도축 정보·등급 평가 정보를 정의하고 파이프라인으로 수집
  • 보정: 전처리와 EDA 로 데이터 보정
  • 비교: 기본 변수만 쓴 경우와 추가 지표를 결합한 경우의 정확도 비교
  • 결합: 알고리즘별 최고 모델을 Stacking Ensemble 로 결합
  • 설명: Feature·Permutation Importance 측정 후 SHAP 으로 변수 간 상관 분석, 활용성 높은 변수를 신규 지표로 추천

월간 예측·강화학습 루프

사업부가 원래 하던 '매월 다음 달 등급 예측 보고' 주기에 모델을 얹었습니다. 예측과 실제 도축 판정 등급을 맞대어 보고, 그 차이로 모델을 계속 개선하는 강화학습 루프입니다. 현업 적용 단계의 학습·튜닝·강화학습은 Databricks 작업 공간(노트북·작업 스케줄)에서 관리했습니다.

개념 데이터 모델

실제 테이블 구조가 아니라 예측에 쓰인 데이터를 일반 개념으로 다시 그린 그림입니다. 개체 단위로 성장 기록·도축·판정 결과를 잇고, 예측 결과에는 그 예측을 만든 모델 버전을, 모델 버전에는 변수 중요도(SHAP)를 남기는 구조입니다. 거래처 쪽은 SFA/CRM 의 거래처·여신 개념을 빌려 고객 등급 예측의 대상으로 두고, 예측에 쓴 여신·미수금과 실제 거래처 매출·주문 데이터를 거래처에 붙였습니다.

모델 운영 단계

논문 검증에서 현업 운영까지 모델이 거친 단계입니다. 사업부에 제공하자 정확도가 한 번 내려갔고, 2개월 튜닝·강화학습을 거쳐 월간 예측 운영에 들어갔습니다.

설계 결정왜 이렇게 골랐나

단일 모델 대신 Stacking Ensemble

같은 데이터로 Random Forest, XGBoost, LightGBM 을 각각 학습해 알고리즘별 최고 모델을 고른 뒤 결합. 한 알고리즘의 약점에 기대지 않고, 개별 모델과 최종 모델의 정확도를 나란히 비교할 수 있게 한 선택.

트리 계열 알고리즘 3종

개체 이력·도축·등급 평가처럼 수치와 범주가 섞인 표 형태 데이터. 변수 중요도를 바로 뽑을 수 있어 뒤의 설명 단계(SHAP)와 잘 맞는 계열로 한정.

SHAP 변수 분석을 사양 관리 지표로 전달

논문 단계의 변수 분석과 신규 지표 추천을 처음부터 현업 적용 계획에 포함. Feature·Permutation Importance 로 전체 중요도를 보고 SHAP 으로 변수 간 관계를 분석해, 활용성 높은 변수를 사양 관리 지표로 제공.

새 업무 대신 기존 월간 보고에 얹기

사업부가 이미 매월 하던 '다음 달 등급 예측 보고'는 그대로 두고 예측 방식만 교체. 수기 예측과 같은 잣대(정확도)로 바로 비교 가능. 예측 오차율 30~40%→9~11%↓ 는 이 정확도에서 환산한 값이며 따로 잰 값이 아님.

주요 기능

축우 등급 예측 대시보드

사육 중인 개체의 성장 데이터와 도축 당시 육질·육량 지표로 도축 시 판정 등급을 예측. 사업부의 월간 등급 예측 보고에 쓰는 화면.

사양 관리 지표

SHAP 변수 중요도 분석 결과를 사양 관리 지표로 정리해 현업에 제공. 어떤 변수가 등급에 크게 작용했는지를 모델 전체 기준으로 정리.

고객 D등급 예측

거래처 여신·미수금과 실제 매출·주문 데이터로 D등급 발생이 예상되는 거래처를 미리 골라 냄. 계산식은 현업과 함께 정했고, 마케터·본부와 미수금·계약 관리 업무에 적용. 정확도 수치는 따로 제시하지 않음.

재튜닝·강화학습

예측과 실제 판정 결과를 비교해 모델을 계속 개선하는 강화학습 루프. 현업 적용 직후 2개월간 하이퍼파라미터·모델 조정, 강화학습, 데이터 추가 확보로 정확도 89~91% 확보.

성과

축우 등급 예측 정확도는 현업 수기 60~70%→최종 89~91%↑. 예측 오차율로 바꾸면 30~40%→9~11%↓(정확도 환산 값). 논문 단계 93% 에서 현업 적용 직후 85% 내외로 내려갔고, 2개월 튜닝·강화학습·데이터 추가 확보로 회복. 고객 D등급 예측은 정확도 수치 없음. 이 AI 프로젝트 성과는 이후 SFA/CRM 이 그룹 계열사 공통 ERP 표준 모델로 채택되는 과정에서도 긍정 요인으로 함께 인정됨.

CASE 02 / 04성능개선

논문 93%가 현업에서 85%로 — 2개월 재튜닝으로 89~91% 회복

문제 현황

정확도 하락
  • 석사 논문에서 100만 건 데이터로 검증한 모델 정확도 93%
  • 사업부에 대시보드로 제공하자 정확도 85% 내외로 내려감
  • 월간 등급 보고에 쓰려면 다시 끌어올려야 함

원인 분석

조정 문제
  • 원인은 하이퍼파라미터·모델 조정 문제
  • 논문 단계 설정을 현업 적용 환경에 맞게 다시 조정해야 함

해결 과정

재튜닝
  1. 예측과 실제 도축 판정 등급을 맞대어 정확도 저하 확인
  2. 하이퍼파라미터·모델 설정 재조정
  3. 예측·실제 판정 비교 강화학습 루프 운영, 데이터 추가 확보
  4. Databricks 작업 공간에서 루프 관리, 2개월 반복·재측정

결과

정확도 회복
  • 정확도 약 85% → 89~91%↑ 회복
  • 현업 수기 대비 오차율 30~40% → 9~11%↓(정확도 환산)
  • 논문 93% 는 참고값, 현업 운영 정확도와 직접 비교 대상 아님
전체 설명 보기
문제 상황

석사 논문에서 100만 건 축우 개체 데이터로 검증한 모델은 정확도 93%였습니다. 같은 모델을 사업부에 대시보드로 제공하자 정확도가 85% 내외로 내려갔습니다. 월간 등급 보고에 쓰려면 다시 끌어올려야 했습니다.

원인 분석

원인은 하이퍼파라미터·모델 조정 문제였습니다. 논문 단계에서 맞춰 둔 설정을 현업 적용 환경에 맞게 다시 조정해야 했습니다.

해결 과정
  1. 예측 결과와 실제 도축 판정 등급을 맞대어 정확도 저하 확인
  2. 하이퍼파라미터·모델 설정 재조정
  3. 예측과 실제 판정을 비교해 모델을 계속 개선하는 강화학습 루프 운영
  4. 데이터 추가 확보
  5. 학습·튜닝·강화학습 루프를 Databricks 작업 공간(노트북·작업 스케줄)에서 관리
  6. 2개월간 조정과 강화학습을 반복하며 정확도 재측정
결과

정확도 85% 내외→89~91%↑. 현업 수기 예측(60~70%) 대비로는 예측 오차율 30~40%→9~11%↓(정확도 환산).

  3. 튜닝 후

    월간 등급 예측 보고에 사용

CASE 03 / 04ETL 파이프라인

출처가 다른 개체·도축·판정 데이터를 학습용 한 벌로

문제 현황

통합 필요
  • 모델 학습 전 소도체 이력·도축·등급 평가 정보 정의·통합 필요
  • 출처는 사내 목장·농장과 공공 축산물 이력 데이터 양쪽

원인 분석

출처 차이
  • 사내·공공 데이터는 만들어지는 곳이 다름
  • 그대로는 같은 개체 단위로 묶어 학습에 쓰기 어려움

해결 과정

수집·가공
  1. 예측용 항목 정의, 사내·공공 데이터를 함께 사용
  2. Airflow 로 정기 수집, Redshift 에 적재
  3. 100만 건 전처리·피처 생성을 Spark 로 분산 처리, EDA 보정
  4. 기본 변수·추가 지표 결합을 나눠 비교, Stacking Ensemble 로 최종 측정

결과

모델 뼈대
  • 100만 건으로 학습한 Stacking Ensemble, 논문 기준 정확도 93%
  • 이 절차가 현업 모델의 뼈대가 됨
전체 설명 보기
문제 상황

등급 예측 모델을 만들려면 소도체 이력, 도축 정보, 등급 평가 정보를 먼저 정의하고 한곳에 모아야 했습니다. 이 데이터는 사내 목장·농장 데이터와 공공 축산물 이력 데이터 양쪽에서 가져왔습니다.

원인 분석

사내 데이터와 공공 데이터는 만들어지는 곳이 달라, 그대로는 같은 개체 단위로 묶어 학습에 쓰기 어려웠습니다.

해결 과정
  1. 예측에 쓸 소도체 이력·도축 정보·등급 평가 정보 항목 정의
  2. 사내 목장·농장 데이터와 공공 축산물 이력 데이터를 함께 사용
  3. Apache Airflow 파이프라인으로 정기 수집, Amazon Redshift 에 적재
  4. 100만 건 규모의 전처리·피처 생성을 Apache Spark 로 분산 처리하고, EDA 로 데이터 보정
  5. 기본 변수만 쓴 경우와 추가 지표를 결합한 경우를 나눠 정확도 비교
  6. 알고리즘별 최고 모델을 골라 Stacking Ensemble 로 최종 정확도 측정
결과

100만 건 축우 개체 데이터로 학습한 Stacking Ensemble 모델이 논문 데이터 기준 정확도 93% 를 기록했고, 이 절차가 현업 모델의 뼈대가 되었습니다.

CASE 04 / 04현업연계

논문 속 변수 분석을 현업으로 — SHAP 변수 중요도를 사양 관리 지표로 제공

문제 현황

논문 분석
  • 논문 단계에서 변수 중요도·SHAP 으로 변수 관계 분석
  • 분석 결과로 신규 지표 후보를 추천해 둠
  • 현업 적용 때 예측과 함께 사업부에 넘기기로 함

원인 분석

설명 한계
  • 앙상블 예측 등급만으로는 부족
  • 어떤 변수가 등급을 움직였는지 드러나지 않음

해결 과정

지표화
  1. Feature·Permutation Importance 로 전체 변수 중요도 측정
  2. SHAP 으로 변수 간 상관 관계·변수별 기여도 분석
  3. 활용성 높은 변수를 신규 지표 후보로 추천
  4. 현업 적용 때 사양 관리 지표로 정리해 예측과 함께 제공

  • SFA/CRM 의 그룹 계열사 공통 ERP 표준 채택 때 긍정 요인으로 함께 인정

문제 상황

논문 단계에서 변수 중요도와 SHAP 으로 변수 관계를 분석해 신규 지표 후보를 추천해 두었고, 현업 적용 때 이 결과를 예측과 함께 사업부에 넘기기로 했습니다.
