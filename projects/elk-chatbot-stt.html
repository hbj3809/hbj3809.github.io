프로젝트 개요
무엇을, 왜 만들었나

2024.12에 직접 구축해 연 그룹웨어 ChatBot(배차 요청·자동배차·회수·담당자 조회)을 2025.02 ~ 05에 ELK 검색과 Whisper STT 기반 전화 ARS로 넓혔습니다. ARS 음성 인식은 현장 방언과 변형어 때문에 40%에 머물렀습니다. Whisper는 그대로 두고, 직원 동의를 받아 모은 실제 통화 데이터로 물류 전용어 사전과 오인식 보정을 키우고 KorpatELECTRA를 파인튜닝하는 Airflow 재학습 파이프라인으로 특정 지역권의 배차 요청·담당자 조회·반납 요청 ARS 업무 기준 80~85%까지 올렸고↑, 업무·지역별 편차는 아직 남아 있습니다. ChatBot 만족도는 내부 직원 분기 설문에서 87점에서 92점↑으로 올랐고, 이듬해 같은 분기에도 92점을 유지했습니다.

개요배경·목표·내 역할

물류 그룹의 그룹웨어와 기간계 시스템에서 쓰는 업무형 ChatBot을 ELK 검색과 Whisper STT 기반 전화 ARS까지 넓힌 프로젝트입니다. 핵심 과제는 표준어 기준으로 만든 언어 처리를 현장의 방언과 변형어에 맞추는 일이었습니다.

  • 배경: 배차 요청·자동배차·회수·반납·담당자 조회 같은 반복 업무를 사람이 응대하던 구조
  • 목표: ChatBot·검색(ELK)·전화(ARS)로 사용자가 업무를 스스로 처리
  • 사용자: 그룹 지주사·계열사 3곳 임직원 1천여 명 + 외부 사용자 약 200명
  • 내 역할: 그룹웨어·기간계 전용 Python API 서버(FastAPI·Flask), 모델 재학습, Airflow DAG(STT·물류 전용어 사전·자연어 처리), KorpatELECTRA 기반 물류 Tokenizer·Analyzer 설계·구현

아키텍처

세 창구(그룹웨어 ChatBot, 기간계 ChatBot, ARS 전화)가 하나의 Python API 계층과 언어 처리 계층을 함께 씁니다. 검색은 ELK 스택으로 새로 구축했고, 통화 전사 수집·색인에도 같은 ELK를 그대로 썼습니다. ARS 음성 인식은 OpenAI Whisper API를 불러 썼습니다.

  • ChatBot: 배차 요청·자동배차·회수·담당자 조회 (그룹웨어·기간계)
  • ARS: 전화 음성으로 배차·자동배차·회수·반납 요청과 담당자 조회 처리
  • ELK 검색: nori 분석기 기반 그룹웨어 검색, 응답 200ms
  • 재학습: Airflow DAG로 STT·물류 전용어 사전·자연어 처리 데이터를 갱신

핵심 흐름 ① ChatBot 질의 처리

질문은 먼저 형태소 분석과 용어 정규화를 거쳐 표준어 질의로 바뀝니다. 업무 유형은 정해 둔 규칙과 파인튜닝한 KorpatELECTRA 분류를 함께 써서 가립니다. 그다음 업무 요청이면 기간계 기능으로, 정보 조회면 nori 색인 검색으로 갈라집니다.

핵심 흐름 ② STT 지능형 ARS

통화 음성을 텍스트로 바꾼 뒤, 현장 변형어를 표준어로 되돌리는 보정 단계를 거쳐 업무로 연결합니다. 같은 '파렛트'도 현장에서는 여러 가지로 발음하기 때문에, 이 보정 단계가 인식 정확도를 좌우합니다.

  • ARS로 받는 업무: 배차·자동배차·회수·반납 요청, 담당자 조회
  • 인식 정확도를 잰 범위: 배차 요청·담당자 조회·반납 요청
  • 보정: 현장 소음과 방언(경상도·전라도) 변형어를 물류 전용어 사전으로 표준어에 매핑
  • 통화·전사 데이터는 직원 동의를 받은 범위 안에서만 재학습에 사용

재학습 데이터 루프

정확도 개선의 중심은 현장 데이터가 학습까지 들어오는 길을 만든 일이었습니다. 처음에는 오인식 단어를 하나씩 손으로 표준어와 묶어 다시 학습했습니다. 이후 수집·전사·색인·사전 갱신을 Airflow 파이프라인으로 이었습니다.

  • 수집: 직원 동의를 받아 시범 기간 동안 영남·호남 영업 조직의 업무 통화를 모음
  • 색인: 이미 운영하던 ELK 스택에 nori 기반 파이프라인을 만들어 인덱스를 갱신
  • 자동화: STT·물류 전용어 사전·자연어 처리 목적의 Airflow DAG 설계·구축
  • 운영: 재학습을 프로젝트가 끝난 뒤에도 상시 운영 업무로 유지
  • 파인튜닝 대상은 KorpatELECTRA(의도·업무 유형 이해)이고, Whisper는 그대로 쓰면서 인식 결과를 전용어 사전으로 보정

개념 데이터 모델

사용 창구는 셋(그룹웨어 ChatBot·기간계 ChatBot·ARS 전화)이지만, 데이터는 질의·통화 전사·업무 유형·용어 사전·학습 데이터로 모입니다. 이 개념도에서는 통화 기록이 반드시 동의 기록을 근거로 수집된다는 원칙을 관계로 표현했습니다.

설계 결정왜 이렇게 골랐나

도메인 언어모델 + 표준어 사전

표준어를 기준으로 물류 도메인 어휘를 사전에 넣고 학습시키려고 KorpatELECTRA를 골랐습니다. ELECTRA 계열 한국어 언어모델이며, 생성형 LLM이 아니라 물류 Tokenizer·Analyzer의 기반으로 썼습니다.

전사 색인도 새 인프라 없이 같은 ELK로

그룹웨어 검색용으로 세워 이미 쓰고 있던 ELK 스택을 통화 전사 수집·색인에도 그대로 활용했습니다. 통화 전사를 nori 기반 파이프라인으로 색인하고, 이 데이터를 전용어 사전 보정과 KorpatELECTRA 파인튜닝으로 이어 붙였습니다.

실제 통화를, 동의를 받고 범위를 정해

표준어 테스트로는 현장 방언을 잡을 수 없었습니다. 그래서 직원 동의를 받아 시범 기간 동안 영남·호남 영업 조직의 업무 통화만 모았습니다.

시범 범위는 현업과 함께

시범 대상 업무(배차 요청·담당자 조회·반납 요청)를 현업과 함께 정했고, 결과도 이 범위와 함께 밝힙니다.

AI 서버는 Python으로 분리

모델과 언어 처리 라이브러리는 Python 생태계에 있습니다. 그래서 기간계와 별도로 FastAPI·Flask 서버를 두고, 그룹웨어·기간계와는 API로만 연결했습니다.

음성 인식은 Whisper, 보정은 전용어 사전으로

음성 인식은 OpenAI Whisper API를 불러 썼습니다. Whisper 자체는 파인튜닝하지 않고 인식 결과를 물류 전용어 사전으로 보정했고, 의미 이해는 파인튜닝한 KorpatELECTRA가 맡게 나눴습니다.

성과 ① STT 인식 정확도

특정 지역권의 배차 요청·담당자 조회·반납 요청 ARS 업무를 기준으로 40%에서 80~85%까지 올렸습니다↑. 전체 통화의 평균이 아니며, 일부 작업 공간의 통화 소음과 현장 어휘 때문에 업무·지역에 따라 지금도 편차가 있습니다.

성과 ② ChatBot 만족도와 운영 지표

2024.12 오픈 기준 87점에서 2025 Q1 92점으로 올랐고↑, 2026 Q1에도 92점을 유지했습니다. 내부 직원을 대상으로 한 분기 설문 결과입니다.

  • 분기 공식 설문 기준 운영 효율 15% 개선
  • 인당 업무시간도 줄었다는 설문 결과
  • ELK 검색 응답 200ms
  • 그룹 임직원 1천여 명 + 외부 사용자 약 200명

원인 분석

방언·변형어
  • 원인은 경상도·전라도 방언과 현장 용어 변형

현업과 함께 정한 시범 업무(배차 요청·담당자 조회·반납 요청)를 전화 ARS로 받으려고 Whisper STT를 붙였습니다. 표준어 테스트에서는 큰 문제가 없었습니다. 하지만 실제 현장 통화에서는 이 업무들의 인식 정확도가 40% 수준이었습니다.

원인 분석

원인은 경상도·전라도 방언과 현장 용어의 변형이었습니다. 같은 '파렛트'를 현장에서는 팔렛·펠렛·빠레뜨·빨레트로 부릅니다. 표준어로 만든 사전과 모델은 이 변형어를 다른 단어로 처리했고, 일부 작업 공간에서는 통화 소음도 더해졌습니다.

해결 과정
  1. KorpatELECTRA 기반 물류 Tokenizer·Analyzer와 표준어 기준 물류 전용어 사전 구성
  2. 초기: 오인식된 예외 단어를 하나씩 표준어와 묶어 사전·보정 규칙에 반영
  3. 직원 동의를 받아 시범 기간 동안 영남·호남 영업 조직의 업무 통화 데이터 수집
  4. 이미 운영하던 ELK 스택에 nori 기반 파이프라인을 만들어 인덱스를 갱신하고, 그 데이터를 전용어 사전 보정과 KorpatELECTRA 파인튜닝으로 연결
결과

특정 지역권의 배차 요청·담당자 조회·반납 요청 ARS 업무에서 인식 정확도가 40%에서 80~85%↑로 올랐습니다. 다만 통화 소음과 현장 어휘 때문에 업무·지역별 편차가 지금도 남아 있어, 만족할 만한 수준이라고 보지는 않습니다.

    운영 중이던 ELK 스택으로 영남·호남 업무 통화를 수집·색인하고 학습 데이터로 연결
    채택된 안: 대상 ARS 업무 기준 80~85%

배운 점

표준어 테스트를 통과해도 현장 통화에서는 통하지 않을 수 있었습니다. 현장 데이터를 동의 범위 안에서 모으는 길을 먼저 만들어야 개선이 이어졌습니다. 결과 수치는 적용 범위(업무·지역)와 함께 밝혀야 정확합니다.

CASE 02 / 03ETL 파이프라인

사람 손에 묶여 있던 재학습을 데이터 루프로

문제 현황

수작업 반복
  • 오인식 단어가 나올 때마다 예외 단어를 찾아 표준어와 묶음
  • 묶은 뒤 다시 학습하는 일을 손으로 반복
  • 이 프로젝트에서 가장 지치게 만든 작업

원인 분석

사람 의존
  • 찾기·묶기·다시 학습, 단계마다 사람 손이 필요
  • 새 통화 데이터의 학습 반영 속도가 사람 손에 묶임

해결 과정

DAG 자동화
  1. 이미 운영 중이던 ELK 스택을 수집·색인 기반으로 재사용
  2. STT·물류 전용어 사전·자연어 처리용 Airflow DAG 설계·구축
  3. nori 색인 갱신 결과를 사전 보정·KorpatELECTRA 파인튜닝 데이터로 연결
  4. 모델 재학습을 프로젝트 이후에도 상시 운영 업무로 유지

결과

상시 운영
  • 수집부터 사전 갱신까지 DAG로 연결
  • 재학습은 프로젝트가 끝난 뒤에도 상시 운영 업무로 남음
  • 대상 ARS 업무 정확도 80~85%는 이 루프 위의 결과
전체 설명 보기
문제 상황

오인식 단어가 나올 때마다 예외 단어를 찾아 표준어와 묶고 다시 학습하는 일을 손으로 반복하고 있었습니다. 이 프로젝트에서 가장 지치게 만든 작업이었습니다.

원인 분석

예외 단어를 찾고, 표준어와 묶고, 다시 학습을 돌리는 단계마다 사람이 손을 대야 했습니다. 새 통화 데이터가 들어와도 학습에 반영되는 속도가 사람 손에 묶여 있었습니다.

해결 과정
  1. 이미 운영 중이던 ELK 스택을 수집·색인 기반으로 재사용
  2. STT·물류 전용어 사전·자연어 처리 목적의 Airflow 파이프라인과 DAG 설계·구축
  3. nori 기반 파이프라인으로 인덱스를 갱신하고 그 결과를 사전 보정·KorpatELECTRA 파인튜닝 데이터로 연결
  4. 모델 재학습을 프로젝트 이후에도 상시 운영 업무로 유지
결과

수집부터 사전 갱신까지 DAG로 이어졌고, 재학습은 프로젝트가 끝난 뒤에도 상시 운영 업무로 남았습니다. 대상 ARS 업무 정확도 80~85%는 이 루프 위에서 나온 결과입니다.

배운 점

모델 정확도보다 먼저 '현장 데이터가 학습까지 들어오는 길'을 만들어야 개선이 계속됩니다. 손으로 반복하는 단계가 보이면 그것이 파이프라인으로 옮길 대상입니다.

CASE 03 / 03서비스운영

오픈 87점에서 92점↑으로, 이듬해에도 92점

문제 현황

서비스 오픈
  • 직접 구축한 그룹웨어 ChatBot을 2024.12 먼저 오픈
  • 오픈 시점(2024 Q4) 내부 직원 분기 설문 87점
  • 사용자: 지주사·계열사 3곳 임직원 1천여 명 + 외부 약 200명

원인 분석

응답 품질
  • 오픈 뒤 실제 질문을 잘못 알아듣거나 엉뚱하게 답하는 경우 발생
  • 검색(ELK)·전화(STT ARS)는 2025.02 ~ 05 확장 범위로 남음

해결 과정

보정·확장
  1. 잘못 알아들은 질문·엉뚱한 답을 모아 사전·학습 데이터로 보정
  2. 같은 시기 확장: ELK 검색(응답 200ms)·Whisper STT ARS 창구 추가
  3. 재학습·사전 갱신 상시 운영, 분기 설문으로 만족도·운영 효율 확인

결과

92점 유지
  • 만족도 87점 → 92점↑ (2024 Q4 대비 2025 Q1)
  • 2026 Q1에도 92점 유지
  • 분기 공식 설문 기준 운영 효율 15% 개선
  • 확장이 시작된 분기라 상승을 한 작업 효과로 단정하지 않음
전체 설명 보기
문제 상황

직접 구축한 그룹웨어 ChatBot을 2024.12에 먼저 열었고, 오픈 시점(2024 Q4) 내부 직원 분기 설문 점수는 87점이었습니다. 사용자는 그룹 지주사·계열사 3곳 임직원 1천여 명과 외부 사용자 약 200명입니다.

원인 분석

오픈 뒤 실제 질문 가운데 ChatBot이 잘못 알아듣거나 엉뚱하게 답하는 경우가 있었습니다. 검색(ELK)과 전화(STT ARS) 창구는 아직 2025.02 ~ 05 확장 범위로 남아 있었습니다.

해결 과정
  1. 오픈 뒤 잘못 알아들은 질문과 엉뚱한 답을 모아 물류 전용어 사전·학습 데이터로 계속 보정
  2. 같은 시기 진행한 확장: ELK 검색(그룹웨어 검색 응답 200ms)과 Whisper STT ARS 전화 창구 추가
  3. 재학습·사전 갱신을 상시 운영하고, 분기 설문 결과로 만족도·운영 효율 확인
결과

만족도는 87점(2024 Q4)에서 92점(2025 Q1)으로 올랐고 2026 Q1에도 92점을 유지했습니다. 분기 공식 설문 기준 운영 효율은 15% 개선됐습니다. 그사이 가장 크게 손본 것은 오인식·답변 보정이었지만, 2025 Q1은 확장 작업이 시작된 분기이기도 해서 점수 상승을 한 가지 작업의 효과로만 단정하지 않습니다.

만족도는 오픈 점수보다 다음 분기, 다음 해에도 유지되는지로 봐야 합니다. 그러려면 재학습과 사전 갱신이 일회성 프로젝트가 아니라 운영 업무여야 합니다.
