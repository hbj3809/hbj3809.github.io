프로젝트 개요
무엇을, 왜 만들었나

물류기기 이동전표가 찢어지거나 구겨져 있어도 무인 키오스크에서 바로 읽어 입고를 확정하도록 만든 Vision AI 입고 검증입니다. 오픈소스 OCR부터 상용 API 단독 사용까지 네 가지 방식을 차례로 시험했지만 모두 기각했습니다. 최종안은 Google Cloud Vision으로 전표 양식의 구역을 잡고, 그 구역의 글자는 PaddleOCR로 읽는 방식입니다. 글자 위치가 아니라 양식의 구역을 기준으로 정보를 찾습니다. 이동전표 기준으로 인식률 100%, 인식 처리 3초 내외를 확인했습니다. 납품 전 1개월 동안 자사 물류센터 현장에서 정상⁠·훼손⁠·입고 거부 상태마다 1,000장씩 시험했습니다. 인식 결과는 고객사 설정에 따라 바로 입고 확정되거나 관리자 검토로 넘어갑니다.

개요배경⁠·목표⁠·내 역할

LOGION은 국내 대형 물류⁠·식품 기업 10여 곳에 도입⁠·납품을 진행한(시범 도입 포함) 무인 수불 자동화 키오스크 솔루션입니다. 이 페이지는 그 가운데 입고 검증을 다룹니다. 도착지 담당자가 눈으로 확인하던 이동전표를 키오스크 카메라와 Vision AI가 읽도록 바꾼 일입니다. 물류 현장의 입고 검증⁠·사내 챗봇⁠·ARS에 Vision AI⁠·NLP⁠·STT를 나눠 적용했는데, 이것은 그중 Vision AI를 맡은 부분입니다.

  • 배경운송기사가 상차하는 동안 사무실에서 신원⁠·상차 정보를 대면 확인받고 출력된 전표에 도장을 받은 뒤, 도착지에서 다시 담당자에게 내역을 확인받던 입고 절차. 담당자가 자리를 비우면 업무가 지연되고 잘못된 전표를 수거할 위험이 있음
  • 목표찢어지거나 구겨진 물류기기 이동전표도 키오스크 카메라로 바로 읽어 입고 확정이나 검토로 연결
  • 내 역할인식 방식 5단계 가설 검증과 하이브리드 인식 구현. 2024.11 부터는 LOGION 총괄 PM으로 입고(Receipt) 업무 경계를 설계하고 입고 업무 흐름에 연동
  • 기간2024.08 문제 정의 → 2024.11 이동전표 기준 인식률 100% 확인(약 3개월 분석⁠·검증). 이후 LOGION 입고 업무에 적용

아키텍처① 출고⁠·입고 이벤트 흐름

출고가 끝나면 출고(Delivery) 서비스가 Kafka로 이벤트를 보내고, 입고(Receipt) 서비스는 이 이벤트를 받아 도착지의 입고 검증 데이터를 미리 준비합니다. 키오스크는 바코드로 입고 건을 입고 서비스에서 불러오고, 촬영한 전표 이미지를 입고 서비스로 보냅니다. 검토가 필요한 건은 관리자 페이지 알림으로 현장 관리자⁠·센터 직원에게 가고, 확정된 입고는 Kafka 이벤트로 EAI를 거쳐 고객사 ERP⁠·내부 기간계 ERP로 이어집니다. 촬영한 전표를 읽는 과정은 다음 도표에 따로 그렸습니다.

아키텍처② Vision AI 연동 서버

입고 서비스는 전표 촬영을 Kafka 이벤트로 넘기고, Python⁠·FastAPI로 만든 Vision AI 연동 서버가 판독 결과를 다시 이벤트로 돌려줍니다. 연동 서버는 OpenCV로 노이즈를 지우고 각도를 바로잡은 뒤, Google Cloud Vision으로 양식의 구역을 잡고 PaddleOCR로 그 구역의 글자를 읽습니다. AI 관련 데이터는 Amazon Aurora에 둡니다.

전표 인식 처리 흐름촬영부터 입고 확정⁠·검토까지

키오스크 카메라로 찍은 전표는 먼저 OpenCV로 노이즈를 지우고 각도를 바로잡습니다. 그다음 Google Cloud Vision이 전표 양식의 구역을 잡고, 그 구역의 글자를 PaddleOCR이 읽은 뒤, 결과를 양식의 구역(핵심 필드⁠·도착지 인감 영역)에 맞춰 배치합니다. 읽은 핵심 필드는 바코드로 불러온 입고 건 내역(품목⁠·수량 등)과 대조하고, 도착지 인감도 확인합니다. 확인이 끝나면 고객사의 입고 정책에 따라 바로 확정되거나 관리자 검토로 넘어갑니다.

입고 검증 흐름바코드 스캔부터 전표 수거까지

도착지에서 하차가 시작되면 운송기사는 키오스크에서 입고를 고르고 바코드로 입고 건을 불러옵니다. 내역을 확인한 뒤 전표를 카메라 앞에 두면, 입고 서비스가 Kafka 이벤트로 판독을 요청하고 Vision AI 연동 서버가 결과를 이벤트로 돌려줍니다. 판독 결과는 고객사 설정에 따라 바로 입고 확정되거나 검토 단계로 넘어가고, 기사는 키오스크 수거함에 전표를 넣으면 업무가 끝납니다.

입고 상태 전이즉시 확정, 검토 후 승인, 반려

입고 건의 상태는 입고 서비스 한 곳에서만 바뀝니다. 고객사에 따라 인식 직후 확정되기도 하고, 검토를 거쳐 확정되거나 반려되기도 합니다.

개념 데이터 모델입고 한 건에 붙는 전표⁠·판독⁠·검토

법인 아래에 하위 센터를 두는 고객사 구조 위에서, 출고 한 건이 도착지의 입고 한 건으로 이어집니다. 입고마다 전표 이미지와 판독 결과, 검토 이력이 붙습니다. 실제 테이블이 아니라 개념 단위로 다시 그린 모델입니다.

설계 결정왜 이렇게 설계했나

엔진 하나 대신 역할을 나눈 두 엔진

오픈소스 OCR, 전처리 강화, 딥러닝 OCR, 상용 API 단독 사용을 차례로 시험했습니다. 방식마다 막히는 곳이 구겨짐, 복잡한 배경, 비용 대비 효율로 서로 달랐습니다. 그래서 Google Cloud Vision은 이미지 맥락으로 전표 양식의 구역을 잡는 데, PaddleOCR은 그 구역의 글자를 읽는 데 써서 서로의 약점을 메웠습니다. OpenCV 노이즈 제거⁠·각도 보정은 단독으로는 구겨짐을 풀지 못했지만, 최종 구성에서도 엔진 앞 전처리로 남겼습니다.

글자 위치가 아니라 구역 기준으로 추출

이동전표는 LOGION이 출력하는 정해진 양식입니다. 하지만 카메라 앞에 놓이는 위치와 훼손 상태는 매번 달랐습니다. 그래서 고정된 글자 위치를 읽지 않고, 양식의 구역(핵심 필드⁠·도착지 인감 영역)을 기준으로 정보를 찾게 했습니다. 찢기거나 비뚤어진 전표에서도 핵심 정보를 읽기 위해서입니다.

자동 확정과 검토는 고객사가 선택

입고 확정 규칙이 고객사마다 달랐습니다. 인식 결과를 바로 확정할지 검토 단계로 넘길지는 고객사 설정으로 나눴습니다. 검토 건은 관리자 페이지에서 업로드된 전표와 추출된 인감 이미지를 보고 확정하거나 반려합니다.

입고 검증은 독립된 경계(Receipt)로

키오스크는 24시간 무인으로 돌아야 했고, 한 업무에 문제가 생겨도 같은 기기의 다른 업무는 계속되어야 했습니다. 그래서 입고 품목 연계, 전표 촬영 검증, 상태 변경을 Receipt 경계에 모으고 출고⁠·관리 서비스와 분리했습니다. 이동전표 같은 출력물의 구성 항목이 바뀌어도 따로 배포할 수 있게 하려는 목적도 있었습니다.

출고 완료 알림은 Kafka 이벤트로

출고 한 건의 결과는 기간계⁠·고객사 연계, 도착지 키오스크의 입고 검증 데이터, 집계, 관리자 알림으로 함께 퍼져야 했고, 장애가 나면 다시 처리할 수 있어야 했습니다. 메시지를 일정 기간 보관하고 오프셋을 되돌려 재처리할 수 있으며, 여러 소비자가 같은 이벤트를 받을 수 있는 Kafka를 골랐습니다.

키오스크 작업 상태는 Redis에

도착지⁠·차량 정보, 인식된 바코드, 전표 촬영 데이터는 한 번의 입고 작업 동안만 필요한 가벼운 상태입니다. 이런 상태는 Redis에 두었습니다.

LOGION의 도입 전후 비교 가운데 입고 검증과 관련된 항목만 옮겼습니다. 현장 오류와 현장 대응 시간은 Vision AI 하나의 효과가 아니라 키오스크 도입 전체의 효과이며, 첫 도입 고객사가 만든 리포트를 기준으로 했습니다. Kafka 비동기 처리로 특정 시간대의 집계 부하를 분산한 개선은 LOGION 플랫폼 페이지에서 다룹니다.

원인 분석

CASE 02 / 03현업 연계

대면 입고 확인 병목 → 키오스크 무인 검증

문제 현황

업무 병목
  • 상차 중 사무실에서 신원⁠·상차 정보 대면 확인, 전표에 도장
  • 도착지 하차 중 담당자에게 내역을 다시 확인
  • 담당자 부재 시 업무 지연, 잘못된 전표 수거도 발생

원인 분석

인력 의존
  • 검증이 사람의 눈과 대면 확인에 묶여 있음
  • 야간처럼 피로가 쌓이는 시간대에 병목⁠·휴먼 에러 집중
  • 휴먼 에러는 재고 불일치 위험으로 이어짐

해결 과정

무인 검증
  1. 키오스크 기준 흐름: 입고 선택 → 바코드로 입고 건 연계 → 내역 확인
  2. 카메라 앞 전표를 Vision AI⁠·OCR로 판독, 도착지 인감까지 인식
  3. 고객사 설정에 따라 즉시 확정 또는 관리자 검토로 분기
  4. 기사가 수거함에 전표를 넣고 종료, 회수까지 한자리에서

결과

업무 전환
  • 입고 확인이 대면에서 키오스크 촬영 검증으로, 인식 3초 내외
  • 현장 대응 시간 평균 8시간 → 1시간↓, 현장 오류 90%↓ 감소
  • 두 수치는 첫 도입 고객사 리포트 기준, 키오스크 도입 전체 효과
  • 입고 업무 현장 클레임 0건
전체 설명 보기
문제 상황

운송기사는 상차하는 동안 사무실에서 신원⁠·상차 정보를 대면 확인받고 출력된 전표에 도장을 받았습니다. 도착지에서는 하차하는 동안 다시 센터나 입고 담당자에게 내역을 확인받았습니다. 담당자가 자리를 비우면 업무가 밀렸고, 잘못된 전표를 수거하는 일도 있었습니다.

원인 분석

검증이 사람의 눈과 대면 확인에 묶여 있었습니다. 그래서 야간처럼 인력을 배치하기 어렵고 피로가 쌓이는 시간대에 병목과 휴먼 에러가 몰렸고, 휴먼 에러는 재고 불일치 위험으로 이어졌습니다.

해결 과정
  1. 업무 흐름을 키오스크 기준으로 재구성: 입고 선택 → 바코드 인식 → 해당 입고 건 연계 → 내역 확인
  2. 카메라 앞 전표를 Vision AI⁠·OCR로 판독하고 도착지 확인 인감까지 인식
  3. 고객사 설정에 따라 즉시 입고 확정 또는 검토 단계로 분기
  4. 검토 건은 관리자 페이지 알림으로 넘기고, 전표⁠·인감 이미지를 확인한 뒤 확정
  5. 업무를 마친 기사가 키오스크 수거함에 전표를 넣고 종료하도록 해 전표 회수까지 한자리에서 처리
결과

  • 확정⁠·승인 외에 반려 업무도 새로 생김
